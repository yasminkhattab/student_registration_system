## 6. Evidence guidelines

Valid evidence includes:

- Git commit hashes or branches authored by the member (visible with
  `git shortlog -sne` and `git log --author="..."`).
- Pull-request or review comments if the group uses a remote repository.
- Screenshots of the screen or test report produced by the member.
- Short demonstration notes showing who implemented and who explained each part.

Invalid evidence: claiming a file without a commit, copying names into this table on
submission day, or listing work that is not present in the repository.

## 7. Individual demonstration preparation

The presentation is **pre-recorded** and every member presents their assigned part.
Each member should be able to:

1. Explain the class they own, its relationships and one design decision behind it.
2. Trace one user action from FXML to controller, service, model and CSV file.
3. Show a unit test they wrote and explain what would break if the rule were removed.
4. Describe one bug they found and how it was fixed.
5. Show one screen or feature they implemented, including its validation messages.

The suggested timing and segment split are in
[`PROJECT_REPORT_OUTLINE.md`](PROJECT_REPORT_OUTLINE.md#6-presentation-plan-pre-recorded).
Record the video before the deadline and keep a copy for every member.
